# DTU geometry and illumination: design audit

This experiment is a classical, calibrated stereo diagnostic that complements the monocular thesis. It tests whether real lighting changes damage geometry and whether modeling radiometric nuisance inside matching helps. It is not a newly invented color-constancy algorithm, an absolute illuminant estimator, or a full DTU benchmark reproduction.

## Primary sources and their implications

- [Official DTU dataset](https://roboimagedata.compute.dtu.dk/?page_id=36) provides calibrated multi-view images under seven lights and structured-light reference geometry. Its original `SampleSet/ReadMe.txt` identifies light **3** as the most diffuse. Supplied projection matrices connect the right-camera rectified RGB images to the left-camera STL coordinate frame; these must be used rather than assuming an unrelated raw-camera calibration.
- [Jensen et al., CVPR 2014](https://www.cv-foundation.org/openaccess/content_cvpr_2014/papers/Jensen_Large_Scale_Multi-view_2014_CVPR_paper.pdf) describes directional lighting generated by groups of LEDs. Thus DTU supports a real **lighting/radiometric robustness** test. It does not supply ground-truth illuminant chromaticities or prove that all observed changes are chromatic rather than shading/exposure.
- [Hirschmueller and Scharstein, TPAMI 2009](https://doi.org/10.1109/TPAMI.2008.221) systematically studies matching costs under radiometric differences, including normalized correlation and Census. Comparing only against raw RGB is insufficient.
- [Heo et al., CVPR 2008](https://iacl.ece.jhu.edu/proceedings/cvpr2008/papers/357.pdf) explicitly models image formation in Adaptive Normalized Cross Correlation (ANCC). [Their TPAMI 2013 paper](https://doi.org/10.1109/TPAMI.2012.167) jointly estimates depth and color consistency. These are direct prior art for integrating color handling into stereo, so integration itself is not a novelty claim.
- [Original MVSNet file specification](https://github.com/YoYo000/MVSNet#file-formats) and [official PatchmatchNet DTU loader](https://github.com/FangjinhuaWang/PatchmatchNet/blob/main/datasets/dtu_yao.py) illustrate preprocessing conventions. Preprocessed cameras can be at feature resolution; image filenames may be one-based while depth/camera IDs are zero-based. Those conventions must not be blindly applied to the original DTU SampleSet used here.

## Implemented controlled comparison

The frozen settings are in `phase2/stereo/protocol.json`, copied with a code hash into each run directory before matching starts. Scene 1 is development/calibration; scene 6 is held out. The three supplied camera views are 25, 26, and 35. A reference image remains at diffuse light 3; the other two views use each real light from 0 through 6. Source light 3 is the matched control. No lighting case is selected according to depth performance.

All five costs share 320 x 240 input images, 256 camera-Z hypotheses over 250-1200 mm, a 5 x 5 support window, camera projection, source aggregation, candidate validity, and winner-takes-all depth selection. There is no learned network, GT initialization, depth-scale fitting, or method-specific smoothing.

1. RGB sum of squared differences (SSD).
2. A local scalar gain optimized within each depth hypothesis: exposure/shading ablation.
3. Three local positive channel gains optimized within each depth hypothesis, regularized toward an input-only global channel-mean ratio: the integrated color/radiometric candidate.
4. Grayscale zero-mean normalized cross correlation (ZNCC).
5. Mean per-channel ZNCC: a stronger color/radiometric baseline.

The scalar and diagonal gains use identical ridge strength 0.002 and bounds [0.25,4]. Images use an inverse-sRGB approximation; the original data are processed RGB rather than radiometrically calibrated RAW. A global channel-mean ratio is a prior, not ground-truth illumination. It can be biased by viewpoint-dependent scene content.

## Why this is integrated, and what is already known

For a reference patch y and source patch x(z), the scalar model minimizes

    mean[(y - a*x(z))^2] + lambda*(a-a0)^2

for every candidate depth z. The solution is

    a = clip((mean[x*y] + lambda*a0)/(mean[x^2]+lambda), lower, upper).

The diagonal model solves this independently for each channel and averages the channel costs. Geometry and radiometric gains are evaluated together inside the matching cost; there is no corrected JPEG fed to an unrelated depth model. Nevertheless, this is classical nuisance-variable optimization.

For an unconstrained affine patch model y = a*x+b, unregularized least squares has residual n*var(y)*(1-rho^2), where rho is the patch correlation. This explains its close relation to ZNCC. Our implemented gain-only, positive, regularized model is not exactly that affine cost, but it must still be compared with established normalized correlation. Arbitrary per-pixel/channel fitting would remove useful material-color information and can explain incorrect correspondences; bounds and priors limit that flexibility.

To establish a color-specific advantage, the diagonal model must add useful geometry accuracy beyond the scalar model and robust baselines. Beating RGB SSD alone demonstrates radiometric sensitivity, not a new color-constancy contribution.

## Geometry and reference validation

- Original projection matrices are decomposed into K, R, and camera center. Their reconstruction must reproduce the supplied 3 x 4 matrix up to its arbitrary projective scale.
- Backprojection followed by projection is checked numerically. This checks implementation algebra but cannot alone establish dataset alignment, so RGB/STL support overlays are also inspected.
- The original STL vertices are z-buffered using camera Z in **millimeters**. Reference holes remain missing; no depth interpolation or GT-based refinement is performed.
- Pixel-center image resizing is applied to the camera matrix. The zero/one-native-pixel origin ambiguity is a development-only convention check, not a fitted GT scale.
- The original foreground plane and GT source visibility define a shared **evaluation** mask. They never enter matching, gain priors, or depth initialization. DTU structured-light data are incomplete, especially on difficult materials, so reference support is reported.
- Primary depth scores are MAE, RMSE, and fractions above 5/10 mm, with shared pixel counts, coverage and nearest-plane quantization error. No submillimeter/full-benchmark claim is appropriate for this low-resolution prototype.
- PLYs under the run's `pointclouds` directory show common evaluation support for fair visual comparisons. Additional `pointclouds_inference` exports retain the full finite algorithm output without a GT mask.

## Statistics and next decision

There is one held-out scene. Report each view/light case and descriptive means; do not treat the views as independent scenes or attach a population confidence interval. A real lighting failure establishes motivation; the candidate may still lose to known robust costs, which must be reported.

A possible later extension is a reference-anchored **global chromatic gain per view plus local scalar shading**, alternately updated from confident geometry correspondences and fed back into depth matching. That would preserve more material-color structure than fitting three unrelated local gains at every hypothesis. It is still literature-inspired and requires careful comparison, held-out scene validation, and a clear distinction between relative color consistency and absolute color constancy. The main monocular study should retain its own datasets and integrated-learning evaluation.
